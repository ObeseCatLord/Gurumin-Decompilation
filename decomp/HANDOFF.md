## How the merges were run (reuse)
- Globals: `python tools/globals_driver.py plan|apply` (docstring). It plans from the current tree, writes the
  headers (keeping their existing rows), rewrites the files, builds, and on a lost match (or > 1 point fuzzy drop in
  a file that saw another type/size) adds the blamed globals to `globals_hold.txt`, restores src/ and include/ from
  HEAD and starts again; files that lose without a blamed global are reverted. Run it on a clean tree.
- Types: `tools/merge_driver.py <config.py> <tag> <files>` (configs in `tools/merge_configs/`). Small merges are
  quicker as a byte-level Python rewrite plus one `build_all.py`.
- Process files as bytes and keep each line's ending; never `sed -i` a CRLF file. Bash heredocs with `\n`/`\r`
  inside Python strings get mangled on this machine: write scripts with the Write/Edit tools. Check
  `git diff --stat` before committing.
- `check_matches.py` reports a renamed symbol as LOST + new. If the address and the count are unchanged, it is a
  rename; update the `obj_symbols.tsv` row, commit, then `check_matches.py` exits 0 against the new HEAD. Compare
  fuzzy per address against HEAD as well.
